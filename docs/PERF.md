# SourceGit 性能基线(M5)

- 测量日期:2026-10-26(机器:Apple Silicon,macOS 27.0)
- 指标:`footprint` 的 `phys_footprint`(真实物理内存占用,不含共享缓存映射;RSS 会高出 40–60MB 属正常)
- 复现:`bash scripts/perf.sh [commits] [history|all|idle]`(生成 fast-import 临时仓库 → release 构建 → 启动 → 采样)

## 结果 vs 预算

| 场景 | 预算 | 实测(6s 峰值 / 12s 稳态) | 结论 |
|---|---|---|---|
| 空闲(无仓库) | < 60MB | 36 / 36 MB | ✅ |
| 1 万提交仓库 · 历史页(分页 800) | < 150MB | 55 / 55 MB | ✅ |
| 5 万提交仓库 · 历史页(分页 800) | < 150MB | 62 / 55 MB | ✅ |
| 5 万提交仓库 · 全量 5 万条历史 | < 300MB | 57 / 57 MB | ✅ |

## 已落地的内存策略(PLAN §2)

1. **历史分页**:默认 800 条,「加载更多」+800;提交数据为轻量值类型(单条 ~250B)。
2. **提交详情懒加载**:文件列表来自 `--name-status` + `--numstat` 摘要(无 hunk);选中文件才取差分 —— 大提交(数百文件)不会一次性解析全部 diff。
3. **diff LRU 缓存**:提交内容不可变,按 `commit|path` 缓存 32 个文件的解析结果,切换文件零重复解析。
4. **渲染虚拟化**:`LazyVStack` 全部长列表;全量 5 万行时 SwiftUI 只物化可见行(实测稳态 57MB,与分页 800 相当)。
5. **单文件 diff 渲染上限 3000 行**(超出提示截断),防止万行文件拖垮 UI。
6. **解析不留双份**:`git log` 按记录 `autoreleasepool` 解析;diff 按行;原始输出解析后即释放。
7. **轮询节流**:每 5s 仅 `git status`;窗口失焦暂停;`allowWhileBusy=false` 与用户操作互斥。
8. **零第三方依赖**:无 WebView / 无内嵌运行时,无额外常驻进程。

## 手动验收项(无自动化,人工确认)

- 5 万提交全量列表滚动:流畅,内存不随滚动上涨(LazyVStack 行复用)。
- 万行大文件 diff:截断提示 + 快速渲染。
- 底部过滤、泳道绘制在 5 万条下无明显卡顿。

## 已知事项 / 后续

- `git log` 全量 5 万条解析在后台线程执行,主线程仅接收结果,无卡顿。
- 后续若引入语法高亮,需评估按行着色的内存成本,再复测本表。
- 滚动性能如仍不达标(备选 NSTableView 降级),重测本表并更新。
